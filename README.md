# PizzaOff

A cozy pizza-party judging app that runs entirely on your computer. Create and resume competitions, register pizza makers and their creations, collect votes, and reveal the results in a password-protected score room.

## Start the app

On Windows, double-click **Start PizzaOff.cmd**. It starts the local server and opens your browser. Keep the terminal window open while judging; press **Ctrl+C** or close it to stop. Run the launcher again whenever you want to resume a party.

The launcher uses Node.js from your PATH, or an installed Codex runtime when available. For a standalone installation, install **Node.js 20 or newer** first. There are no package dependencies and no installation command is required.

From a terminal on Windows, macOS, or Linux:

```sh
node server.mjs
```

Then open **http://127.0.0.1:3210**. `npm start` also works if npm is installed. Set the `PORT` environment variable to choose a different port.

## Run a pizza party

1. Create a competition with a name, at least one contestant, and a score password of 4–128 characters. Use a password you can remember; there is no password recovery.
2. Add pizzas and choose the contestant who made each one. You can add more contestants at any time.
3. Enter votes by selecting the voter and pizza, then choosing **1–5** for Taste, Texture, and Creativity. A contestant cannot vote for their own pizza or vote twice for the same pizza. Votes are final once submitted.
4. Open the score room with the competition's password. Browse Accolades, Score Totals, Score Distributions, and Voter Data. Lock the score room when returning to voting.
5. Your competition saves automatically after each successful change. Resume it from the home screen later.

## How scoring works

- Taste, Texture, and Creativity each have equal weight. A pizza's overall score is the mean of its three category averages, equivalently the mean of all its ballot scores.
- Best Taste, Best Texture, and Most Creative use the highest average in that category. Honorable Mention uses the highest overall average; Dishonorable Mention uses the lowest overall average.
- Ties share the award. Pizzas with no votes remain unscored and do not receive awards; a single rated pizza can hold both highest and lowest awards.
- Distributions count **votes**, not pooled category ratings. Each ballot contributes one observation to each category and one observation to the overall chart: `(taste + texture + creativity) / 3`. Overall observations can fall at thirds, such as 3⅓. One `(1,1,1)` ballot and one `(5,5,5)` ballot therefore produce one observation at 1 and one at 5 on every chart. They do not produce three observations at each endpoint.
- Voter Data shows each contestant's ballots and the average across categories for each ballot.

## Storage and privacy

Competitions are saved in **data/competitions.json** next to the app. This file survives browser refreshes, browser storage clearing, and server restarts. To back up or move your parties, stop the app and copy the entire `data` folder with the app. Do not edit this file while the server is running. No data is uploaded and the app needs no internet connection.

The server listens only on `127.0.0.1`; other devices on your network cannot connect. Passwords are stored as salted scrypt hashes. Raw scores are withheld by the API until the password is accepted. Access expires after two hours or when the score room is locked, and server restarts invalidate all access tokens. Contestants identify themselves by name at this shared device; the app does not authenticate individual voters.

The password is a reveal gate for the party, not encryption of the saved file. Anyone with access to this computer and its data file can inspect the stored ballots. Protect or back up that folder accordingly.

## Development and verification

The app uses only Node's built-in server, cryptography, and filesystem modules plus browser-native HTML, CSS, JavaScript, and SVG. No build step is needed.

```sh
node --test
```

Tests use temporary data directories and never touch your real competitions. They cover persistence, password access and expiry, competition isolation, self-vote and duplicate-vote prevention, score validation, and local request boundaries.
